# План реалізації REST API для контактів

## Мета

Створити REST API на FastAPI для зберігання контактів у PostgreSQL. Для роботи з базою даних використовувати SQLAlchemy, а для валідації та опису даних — Pydantic.

## Етапи реалізації

1. **Підготовка проєкту — виконано**
   - Визначити структуру застосунку та перелік залежностей.
   - Налаштувати підключення до PostgreSQL через змінну середовища.
   - Зберегти Docker Compose для запуску бази даних.

2. **Модель і доступ до даних — виконано**
   - Створити модель SQLAlchemy для контакту.
   - Додати поля: ім’я, прізвище, email, телефон, дата народження та необов’язкові додаткові дані.
   - Налаштувати сесію бази даних і залежність FastAPI для доступу до неї.

3. **Схеми та валідація — виконано**
   - Створити Pydantic-схеми для створення, оновлення та відповіді.
   - Перевіряти коректність email та типів полів.
   - Забезпечити часткове оновлення контакту.

4. **CRUD-ендпоїнти — виконано**
   - Реалізувати створення та отримання списку контактів.
   - Реалізувати отримання контакту за ідентифікатором.
   - Реалізувати оновлення та видалення контакту.
   - Повертати відповідні HTTP-статуси, зокрема `404` для відсутнього контакту.

5. **Пошук і дні народження — виконано**
   - Додати пошук за ім’ям, прізвищем або email через query-параметр.
   - Додати окремий ендпоїнт контактів, у яких день народження припадає на наступні 7 днів.
   - Коректно врахувати перехід між роками.

6. **Документація та перевірка — виконано**
   - Описати встановлення залежностей, запуск PostgreSQL і застосунку.
   - Використовувати автоматичну документацію FastAPI за адресою `/docs`.
   - Перевірити конфігурацію Docker Compose, запуск застосунку та основні сценарії API.

## Критерії готовності

- Контакти зберігаються в PostgreSQL через SQLAlchemy.
- Працюють усі CRUD-операції, пошук і вибірка днів народження на найближчі 7 днів.
- Дані валідовуються Pydantic-схемами, а API має інтерактивну документацію.
